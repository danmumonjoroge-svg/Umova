# Elimu AIA — activities, production and inventory

AIA means Appropriation in Aid: income generated by school-owned activities such as poultry, livestock, dairy, crop farming, horticulture and fish farming.

## Included
- Activity register with type, location, description and responsible manager.
- Income and operating expense records with date, category, quantity, unit, unit price and reference.
- Activity-level and overall operating totals: income, expenses and operating surplus.
- Remittance requests with pending, approved, rejected and paid states.
- Tenant-scoped accounting event outbox. New AIA income and expense records, and remittances transitioning to PAID, create one idempotent balanced two-line journal proposal.
- Accounting tab shows proposed journal lines and current hand-off status.
- Production batches/cohorts for poultry flocks, livestock/dairy herds, crop cycles and fish ponds. Current batch quantity is derived from opening quantity plus additions less mortality.
- Production records for quantity-in, mortality, eggs/milk/harvest/yield and notes.
- Farm-input inventory for feed, veterinary supplies, seeds, fertilizer, fuel, tools and packaging.
- Append-only stock movements for receipts, issues and adjustments. Stock on hand is maintained atomically from the append-only movement ledger; database triggers serialize receipts/issues and reject issues beyond available stock.
- Tenant and finance-permission RLS for every new operational table.

## Database migrations
Apply in order after the POS core migrations that provide `lb_businesses`, `get_current_tenant_id()`, `pos_has_permission()` and the `authenticated` role:
1. `sql/001_elimu_aia.sql`
2. `sql/002_elimu_aia_accounting_outbox.sql`
3. `sql/003_elimu_aia_production_inventory.sql`

Neither the earlier AIA migrations nor this new migration have been applied to the user's live database in this environment. Apply and test them first on a disposable/staging database. Migration 003 assumes PostgreSQL support for `security_invoker` views (PostgreSQL 15+).

## Accounting boundary — important
Migration 002 creates an outbox, **not a posted general-ledger journal**. Events start in `NEEDS_MAPPING`. Account keys are provisional (`AIA_RECEIVABLE_CLEARING`, `AIA_INCOME`, `AIA_OPERATING_EXPENSE`, `AIA_PAYABLE_CLEARING`, and school cash/bank clearing keys). The supplied project does not include the authoritative Elimu finance SQL migration that defines the GL posting tables and exact RPC contract. Therefore this phase deliberately does not guess column names, create duplicate GL tables, or mark an event posted.

Production yields and inventory movements are operational subledgers only. Biological asset valuation, weighted-average/FIFO costing, cost-of-production journals, procurement auto-receipts, GL posting, bank/M-Pesa reconciliation and AIA reversals remain unimplemented pending the verified finance/procurement schema and accounting policy.

## Controls and limitations
- Batch count is opening quantity plus `QUANTITY_IN` less `MORTALITY`; the database locks a batch row before reducing its count.
- Stock on hand is receipts and positive adjustments less issues and negative adjustments; the database locks an inventory item before applying each movement.
- Production and stock events are append-only through the granted authenticated permissions. A correction should be recorded as a compensating event; no delete/edit UI is provided.
- The UI blocks an obvious stock issue above the displayed balance, and the database trigger repeats that check under a row lock for concurrent users.
- No automated GL entry is created from production or stock events in this phase.
